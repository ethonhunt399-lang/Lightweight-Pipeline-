# 结构净高预估：施工图翻模结构接入（2026-10-02）

## 目的

机电还没建模时，用施工图翻模得到的结构，提前给出"梁底 / 板底距下层楼面"的分区图。用于投标和方案阶段回答净高问题，
也把翻模里**推定**的构件尺寸单独标出来，推定构件控制的低净高区应作为图纸问题提给设计确认。

## 改动

| 项 | 内容 |
| --- | --- |
| 数据模型 | `Element` 增加 `basis`（构件依据）、`inferred`（尺寸为推定）、`footprint`（板的平面轮廓与洞口） |
| 净高分区图 | 有轮廓的板参与分区图（格子中心在轮廓内、不在洞口内）；同高时图纸给定构件优先于推定构件；新增 `summary()` 分档统计 |
| 碰撞检测 | 板（`slab`）不参与碰撞、净距检测 |
| 预览器 | 推定构件单独成层（`梁（推定）`）；构件信息显示"依据"；分区图斜纹标出推定构件控制的格子，图例列出推定面积；点击板控制的格子显示板的信息（板不画） |
| 读取 | 新增 `structjson.py`：施工图翻模结构 JSON → `Package` |
| 命令 | 新增 `lwp struct`：输出 `view.html`、`headroom.json`、`headroom_grid.npz` |
| 测试 | `tests/test_structjson.py`：板洞、推定判断、梁下与板下净高、板不进碰撞与三维 |

导出包（RevitBridge）路径不受影响：导出包里没有带轮廓的板，`inferred` 默认 False。

## 首个数据：罗湖美术馆 1栋 一层

结构来自 SLBH 仓库 `projects/luohu/data/structure_1F_v2.json`（墙柱定位图、二层梁配筋图 X/Y、二层结构布置图；投标级翻模）。

```bash
uv run lwp struct structure_1F_v2.json --title "罗湖美术馆 1栋 一层 结构净高预估" --min-clear 3800 --out headroom_1F
```

- 162 跨梁，其中梁高推定 33（就近相似、默认截面、双T板肋）。
- 分档（3.8 m 只是分档基准，不是设计要求）：< 3.8 m 59.5 m²（推定控制 27.2 m²）；3.8–4.0 m 76.2 m²；4.0–4.2 m 73.0 m²；
  4.2–4.6 m 760.5 m²；≥ 4.6 m 1042.5 m²（板底 4.82 m，净高 4.88 m）。
- 最低 3.66 m：KL17(4A) 400×1100，顶 4.700，梁高按图。
- 第二低 3.70 m：无集中标注的 20 m 跨 L 梁按默认 L/15 取 800×1300，为推定，应提请设计确认。

## 已知不足

- 网格 0.5 m，构件外扩半格（与机电分区图同口径），梁下面积偏大，适合看分布，不宜作面积结论。
- 罗湖双T板区（结构布置图注 4.100～4.700 预应力板）在结构 JSON 里仍按 4.940 统一板顶，肋间净高偏高；肋高 800 为推定。
- 柱、墙为轮廓拟合的包围盒（L 形墙偏大，不影响净高）。
- 轴网只收能对上轴号的线（偏差 ≤ 0.5 m）。

## 补充：改读结构数据格式 v1（同日）

- 翻模线定了正式格式 slbh.structure v1（规范副本 `docs/structure-v1.md`，源在 SLBH 仓库 `tools/struct/`）。
  `structjson.load_structure` 自动识别：v1 构件以 `uuid` 为身份，`basis.inferred` 取自文件；旧写法保留一个版本。
- 罗湖一层 v1 结果与旧写法逐项一致（梁 162、推定 33、覆盖 2011.8 m²、各档面积、最低 3.66 m）；唯一变化是板在 v1 里
  标为推定（板厚、板顶未按板参数表分区），所以 ≥ 4.6 m 一档的"推定控制"面积从 8.2 m² 变为 1023.2 m²。
- 测试样例 `toolbox/tests/data/structure_minimal.v1.json` 为合成数据。
