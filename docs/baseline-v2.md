# 轻量化 Web 管综排布工具 · 技术基线 v2

Sep 28, 2026 · @Ethon Hunt

本版按新定位重写：项目自用，Claude 是排布的执行核心，工程师提要求、审 PDF、批准；不接 Claude API，不做多用户 Web 产品；综合支吊架是必达目标。原稿仅作参考，以本文档为准；R0 任务书、数据协议、工程口径与规则 是给开发代理的执行依据。

## 1. 产品定位

这是一套 Claude 驱动的管综深化工作台，只供本团队使用。工作流是 Revit → 现有工具导出 → Claude 调用确定性工具完成排布、综合支吊架和 PDF 出图 → 工程师审核 → 回写 Revit。

成果有四项：管综方案、综合支吊架方案、PDF 图纸与报告、Revit 实模更新。没有支吊架的深化不算完成。

## 2. 分工原则

- **Claude 是执行核心。** 在 Claude Code 会话中理解要求、写约束、调用工具、比较方案、解释和诊断、写报告。
- **硬数值全部来自确定性工具。** 坐标、碰撞、净距、净高、支吊架间距与选型验算、图纸几何都由程序计算；Claude 不计算、不转录数值。
- **工程师是审核者。** 提要求、看 PDF、指出问题、批准；批准后才回写。
- **工具离开 Claude 仍能在命令行运行，每一步都可复现。** 方案记录约束、规则集和工具版本。
- **数据留在本机。** 不接 Claude API，没有中转服务、预算和别名机制。
- **Revit 是正式模型层。** 只在批准后回写。

## 3. 目标架构

&#91;embedded content: 目标架构 · Claude 会话 + 确定性工具箱\]

工具箱是一套 TypeScript 包，既可以命令行运行，也作为本地 MCP Server 暴露给 Claude Code；没有中转服务、API Key 和别名机制，数据留在本机。Claude 在会话中调用这些工具，工程师通过 PDF 审核，批准后由回写工具执行。

不再做浏览器编辑器；如果以后需要三维审阅，可在 R4 加一个只读的 HTML 查看器。

## 4. 路线

&#91;embedded content: 路线 · R0 到 R4 与两道 Pilot 门槛\]

| 阶段 | 交付 | 工程师得到什么 |
| --- | --- | --- |
| R0 数据与检测 | 导出适配、标准化、检测、区段包络剖面、PDF 体检报告，CLI + MCP | 一段走廊的冲突、净距、净高全部列在 PDF 剖面上，结果与 Navisworks 一致 |
| R1 排布求解 | 分层求解器、约束文件、三方案、LayoutPlan、方案 PDF | 口述要求，Claude 给出三个可审的方案 |
| R2 综合支吊架 | 分层分组、间距、型式、选型验算、支吊架表、剖面与平面图 | 带支吊架的完整深化成果 |
| R3 回写 Revit | 管线移动与支吊架族放置、前置校验、回滚 | 批准后实模自动更新 |
| R4 整层扩展 | 自动分区、图求解、抗震支吊架、可选 HTML 查看器 | 整层批量处理 |

**排布求解思路（R1，现在就影响数据设计）**：

- 分层排布：先定每根管线所在的层和层内顺序，再逐层堆叠算坐标，同层外底平齐。层就是综合支吊架的横担，R2 直接沿用。
- 出线方向约束：需要向某侧拐出走廊的管线排在该侧或上层。
- 沿走廊按事件切分区段（梁高变化、变径、支管引出、宽度变化），每段生成候选截面，用动态规划选“各段代价 + 段间翻弯代价”最小的组合；R4 把链推广为图。
- 碰撞和净距是硬约束；软目标按字典序或 Pareto 前沿，输出净高最优、改动最少、支吊架最省三个方案。
- 无解时输出冲突约束集，Claude 据此向工程师解释并建议放松哪条。
- 每个方案记录约束文件、规则集版本、工具版本和随机种子，可复现。

**要求如何变成约束**：工程师在会话中口述，Claude 写成约束文件（硬约束与软偏好分开，每条带作用范围和原话），回显确认后才调用求解器；约束文件随方案归档。

## 5. Pilot 两级验收

R1 结束时通过 Pilot-1，R2 结束时通过 Pilot-2；两级都以 PDF 为审核介质。

| 验收项 | Pilot-1（R1 后，Claude 排布） | Pilot-2（R2 后，含综合支吊架） |
| --- | --- | --- |
| 对比基线 | 同一段真实走廊，工程师在 Revit 中手工排布的版本 | 同一段走廊的人工支吊架深化版本 |
| 时间目标 | 从导出到三个方案 PDF，耗时低于人工排布 | 从方案确认到支吊架图纸，耗时低于人工深化 |
| 结果要求 | 无硬碰撞，满足规则集的净距和净高；工程师至少采纳一个方案 | 支吊架间距、型式和选型被工程师采纳，允许小幅修改 |
| 检测可信度 | 与 Navisworks 或 Revit 碰撞检查逐条对照，差异都能解释 | 选型验算经工程师抽查复算 |
| 成果形式 | 剖面 PDF 与冲突报告 | 剖面、平面、支吊架表 PDF |
| 评价方式 | 工程师打分：碰撞、规范、规整美观、可施工性、改动量 | 同左，加支吊架数量与用钢量 |

## 6. Revit 侧方案

- **输入**：沿用现有 Revit 导出工具，按《R0 任务书》第 9 节的字段清单补齐缺项，不新写导出器。
- **抽查**：现有 Revit MCP 随机读取构件对照导出值。
- **回写（R3）**：优先在现有 MCP 上增加受控命令 apply\_layout\_plan、apply\_support\_plan、rollback\_plan；做不到再写 C# 插件。命令必须支持 dry\_run、逐项 expect 校验、工作共享占用和 Pinned 处理、TransactionGroup、幂等和 partial\_success 明细。
- **支吊架族**：回写需要你们的支吊架族库（成品支吊架或型钢），待确认。

## 7. 综合支吊架目标（R2）

排布的层就是支吊架的横担，所以 R1 的分层结果直接进入支吊架设计。

- **布置**：沿走廊按各管线的最大间距取最严值布点；避开洞口、管件和阀门检修位；支管引出、翻弯、变径两侧加设；生根于板底或梁侧。
- **型式**：门型、单侧悬臂、倒 L 型；多层时同一吊杆上多道横担。
- **选型验算**：荷载取管道自重加满水加保温、风管与桥架自重加电缆，乘安全系数；验算横担弯矩与挠度、吊杆拉力、锚栓；型材和锦栓目录由你们提供。这是简化验算，正式计算书由工程师复核。
- **输出**：SupportPlan（编号、位置、型式、横担长度与规格、吊杆规格、生根方式、所承管线）、支吊架表、剖面与平面图上的表达、R3 的族放置。
- **暂不做**：抗震支吊架（R4）。

## 8. 不做清单

- Claude API 接入、中转服务、多用户 Web 产品、账户与权限
- 浏览器编辑器（只读 HTML 查看器在 R4 可选）
- CDE、BIM 云平台、多人协作、IFC Authoring、通用 IFC 导入、Revit 替代
- 全建筑自动路由、任意 AI 代码执行、Revit 实时双向同步
- DWG 出图（PDF 满足即可，DWG 另行决定）

## 9. 风险总表

| 风险 | 阶段 | 应对 |
| --- | --- | --- |
| 现有导出工具字段不足或格式不稳 | R0 | 先拿样例文件对照字段清单，缺项在工具中补；导入体检报告 |
| 尺寸与净高口径不统一 | R0 | 口径写入《工程口径与规则》，按含保温外轮廓计算 |
| 单切面漏梁、坡度管、链接坐标 | R0 | 包络剖面、标高范围、manifest 记录变换（用例 C02、C03、C08、C09） |
| 系统映射不全、模型质量问题 | R0 | 映射表加体检报告，Claude 提映射建议、人工确认 |
| PDF 不符合图面习惯 | R0 | 先定图框与标注样式，工程师看样张后再批量出 |
| 开发代理无法运行 Revit | R0、R3 | 逻辑全在 TS 侧自动测试；Revit 侧由你运行并回传 |
| Claude 判断失误 | R1 | 数值全部由工具输出；约束回显确认；方案必经 PDF 审核 |
| 求解器无解或方案不合理 | R1 | 冲突约束集诊断；三方案对比；金标准答案集 |
| 支吊架选型责任 | R2 | 简化验算加人工复核；型材目录和安全系数来自你们 |
| 支吊架族库与回写兼容 | R3 | 先用一个族试放置；工作共享和 Pinned 逐项报告 |
| 导出后模型继续变更 | R0、R3 | 基线哈希加 expect 前置校验 |
| 整层规模 | R4 | 分区、图求解、增量检测 |
| 工程责任 | 全程 | 方案状态流转记录确认人和时间 |
